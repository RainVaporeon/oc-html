# In-game check: release 0.7.0a

Goal: check tabs, shell tab-out and downloads in game. Run the steps in
order. Mark each item pass or fail, and paste back the exact text of every
failure. Record the values where an item asks for one ("Record:").

Rules for this list:
- Minecraft catches Esc in game. No check uses Esc. A blank Enter cancels
  every prompt.
- Items marked "Record" have no fixed expected result. Write down what you
  see.

Note: the repository is not pushed yet. Copy the files by hand as for 0.6.0a
(the release folder `releases/0.7.0a/`, or `html-install.lua` from it, goes
into the game by the way you used for 0.6.0a). Then `<BASE>` below means that
copy.

Needs: an Internet Card, a server that allows web requests, a keyboard with
NumPad, a stopwatch, a server with a small ZIP file, a PNG file and a 1 MB
file (a page that serves them, or any host), a second small hard disk or
floppy for the disk-space check, and a computer you can rebuild with 1 and
with 2 sticks of tier 3 memory.

Pages used below: a Wikipedia article (links to other articles), a slow page
as in the 0.6.0a list, `http://example.com/` and a missing URL (404).

## 1. Install and upgrade

```
wget -f <BASE>/releases/0.7.0a/html-install.lua /home/html-install.lua
/home/html-install.lua
ls /home/lib/html
```

- [ ] 1.1 New install: it prints `html-install: oc-html 0.7.0a`, one
  `<path> <size> bytes` line per file, and `installed 13 files`.
  Expected: `tabs.lua` and `download.lua` are in the list.
- [ ] 1.2 Upgrade over 0.6.0a: the same lines. Expected: no `.old` or `.new`
  file stays in `/home/bin` or `/home/lib/html`. It never prints
  `; old files kept`.
- [ ] 1.3 `html --help` lists `t`, `c`, `<`, `>`, `!`, Ctrl+S and `--tabs`.

## 2. Tabs

Start with `html https://en.wikipedia.org/wiki/Lua_(programming_language)`
(or any page with many links).

- [ ] 2.1 Press `t` with a link selected. Expected: the page of the link
  loads, a new tab opens after the current one at the commit, and the status
  shows the prefix `[2/2] `.
- [ ] 2.2 Press `t` with no link selected (press Home or scroll until no link
  shows). Expected: the status row shows ` New tab: `. Type
  `example.com` and press Enter. Expected: a new tab opens with that page
  (`[3/3]`).
- [ ] 2.3 Press `t`, type a few characters, press Backspace once, then
  Backspace until the text is empty, and press Enter. Expected: Backspace
  deletes one character, and a blank Enter cancels. No tab opens.
- [ ] 2.4 Press `<` and `>`. Expected: the previous and the next tab show at
  once, with the prefix `[i/n]`. The order wraps (`>` on the last tab shows
  tab 1, `<` on tab 1 shows the last tab).
- [ ] 2.5 Switch to a tab that you visited before, and back. Expected: a page
  in the cache shows without a download (cache hit). Check that no
  `Loading <n> KB` text shows for it. Record: the time of one switch.
- [ ] 2.6 Open tabs until the limit (8 by default) with `t`. Press `t` once
  more. Expected: the notice `tab limit: 8 tabs` shows until the next key and
  no tab opens.
- [ ] 2.7 Press `c`. Expected: the status row shows ` Close tab? (y/n)`.
  Press `n`. Expected: nothing changes. Press `c` and then another key (for
  example `x`). Expected: it cancels. Press `c` and then Enter. Expected: the
  tab closes and the tab to the right shows (or the left one, when it was
  the last). Press `c` and `y`. Expected: the same.
- [ ] 2.8 Close tabs until one is left, and press `c`. Expected: the notice
  `last tab: q quits` shows and no prompt opens.
- [ ] 2.9 A switch during a load, phase 1. Open a slow URL with `g` and press
  `>` while the status shows `Connecting` (use `http://example.com:81/` or a
  slow host). Expected: the load stops and the other tab shows. Go back with
  `<`. Expected: the load of the first tab starts again (the pending load).
- [ ] 2.10 A switch after the commit. Start a slow page, wait until some
  lines show, then press `>`. Expected: the load stops and the other tab
  shows. Press `<`. Expected: the slow page loads again from the start (it
  is not in the cache because it did not finish).
- [ ] 2.11 A `t` during a load. Start a slow page and press `t` with a link
  selected on the loaded part. Expected: the load of the current tab stops,
  the link of the `t` loads, and a new tab opens at its commit. Record what
  the first tab does when you return to it.
- [ ] 2.12 `c` during a load, then `n`. Expected: the load goes on behind the
  prompt. Then `c` and `y`. Expected: the load stops and the tab closes.
- [ ] 2.13 An `[error]` tab. Press `g`, enter a missing URL (404) in a tab.
  Expected: the popup shows with `[OK]`. After `[OK]`, press `>` and `<`.
  Expected: the tab shows its old page, or `[error] <target>` when it had no
  page. No popup shows again. `r` reloads it.
- [ ] 2.14 Quit with 1 tab. Press `q`. Expected: ` Quit? (y/n)`. Press `n`.
  Open 3 tabs and press `q`. Expected: ` Quit and close 3 tabs? (y/n)`. Press
  `n`, then `q` and `y`. Expected: the program quits and the screen is
  restored.
- [ ] 2.15 Set the resolution to 50x16 (`resolution 50 16`), start `html` with
  2 tabs, and press `?`. Expected: the key list shows `t`, `c`, `<`, `>`,
  `!`, Ctrl+S, fits on the screen or scrolls, and closes with a key. The
  status line with `[2/2] ` stays readable. Then `resolution 160 50` to
  restore the screen.
- [ ] 2.16 Memory over many switches. Open 5 tabs with Wikipedia pages. Press
  `>` 30 times. Expected: no memory popup shows. Record: free memory (`free`
  or `computer.freeMemory()` in the shell) before and after.

### 2a. The `--tabs` option (experimental)

- [ ] 2a.1 `html --tabs 0`, `html --tabs 33` and `html --tabs x`. Expected:
  each prints `html: --tabs needs a number from 1 to 32, or auto` and exits.
- [ ] 2a.2 `html --tabs 3 <page>`. Open tabs with `t`. Expected: the notice
  `tab limit: 3 tabs` shows at the 4th tab.
- [ ] 2a.3 `--tabs auto` with 1 stick of tier 3 memory. Open tabs with
  Wikipedia pages until the notice shows. Record: the limit that the notice
  prints, the free memory at the start, the free memory at the limit. Check
  the notice `not enough memory for a new tab` when it shows.
- [ ] 2a.4 The same with 2 sticks of tier 3 memory. Record the same values.
  Expected: the limit is higher than with 1 stick.

## 3. Shell tab-out

Start with 2 tabs open and scrolled down.

- [ ] 3.1 Press `!`. Expected: the screen clears, the line `html: shell started.
  Type exit to return to the browser.` shows and a shell prompt shows. Run
  `ls`. Expected: the shell works.
- [ ] 3.2 Type `exit`. Expected: the browser returns, with the same tabs and
  the same active tab. The active tab shows again at the same position.
- [ ] 3.3 The Enter after `exit`. Hold Enter a moment as you type `exit`.
  Expected: the key-up of Enter does not follow a link and does not quit.
- [ ] 3.4 `!`, then `resolution 80 25`, then `exit`. Expected: the browser
  uses the new width. Quit with `q` and `y`. Expected: the screen is restored
  to 80x25 (the state at the last tab-out), not the first resolution.
  Run `resolution 160 50` to restore.
- [ ] 3.5 `!`, then run `html` in the shell. Expected: it prints
  `html: already open; type exit to return to it` and exits with code 1
  (`echo $?`). This also checks that `os.setenv` reaches the child process.
  Record: if `html` starts, this is a fail, and the env guard does not work.
- [ ] 3.6 `!`, then press Ctrl+C in the shell (at the prompt, and while a
  command such as `sleep 5` runs). Expected: the shell stays or returns to a
  prompt, and html does not end. Record: what Ctrl+C did at each place.
- [ ] 3.7 `!` during a load of a slow page. Expected: the load stops, the
  shell starts. After `exit`, the tab loads the page again (pending).
- [ ] 3.8 Free memory in the shell. Record: `free` in the shell with 1 tab,
  and with 5 tabs open. Compare with the value outside html.
- [ ] 3.9 `!` during a download (see 4.7). Expected: the notice
  `download running: z stops it`, and the shell does not start.

## 4. Download

Use a text page for 4.1 to 4.6.

- [ ] 4.1 Press Ctrl+S with no link selected. Expected: the status row shows
  ` Save to: <path>` with the working directory and the file name. Record:
  does the game send char 19 or code 31 with Ctrl? (If Ctrl+S does nothing,
  say so.) Check that `d` does nothing.
- [ ] 4.2 The default path is plain text, with the cursor at its end. Press
  Backspace a few times. Expected: it deletes one character each time.
- [ ] 4.3 A blank Enter (delete all text, press Enter). Expected: the prompt
  closes and nothing is saved.
- [ ] 4.4 Accept the default path with Enter. Expected: the notice
  `Saved <path> (<n> KB)` shows. `ls -l` shows the same size.
- [ ] 4.5 The saved bytes are the raw HTML of the current page. Run
  `cat <path>` or open it with `edit`. Expected: HTML source, not the
  rendered text.
- [ ] 4.6 Select a link to a PNG or ZIP file and press Ctrl+S. Expected: the
  file saves. Record: the size of the file against the size on the server.
  (Compare with `wget` of the same URL if you can.)
- [ ] 4.7 A 1 MB file. Record: the free memory before and during the
  download. Expected: it stays flat. The status shows
  `Downloading <name> - <n> KB of <m> KB` and grows.
- [ ] 4.8 Press `z` during a download. Expected: the notice
  `download stopped`. `ls <dir>` shows no file and no `.part` file.
- [ ] 4.9 Download to a name that exists. At ` Overwrite <name>? (y/n)`:
  press `n`, then try again and press Enter. Expected: both keep the old
  file. Try again and press `y`. Expected: the file is replaced.
- [ ] 4.10 Enter a directory as the path (for example `/home`). Expected: the
  default file name is added to it.
- [ ] 4.11 Enter a path in a missing folder (for example `/nothing/x.html`).
  Expected: the popup `html: no such directory: /nothing`.
- [ ] 4.12 The disk-space popup. Save to a small disk (a floppy, or a disk
  with little free space) with a file that is larger than its free space.
  Expected: the popup `html: not enough disk space: <n> KB needed, <m> KB
  free`, and no `.part` file stays. Record: whether it showed before the
  first read (with `Content-Length`).
- [ ] 4.13 Download a URL that gives 404. Expected: the popup with `[HTTP 404]`
  and the URL, and no file.
- [ ] 4.14 Ctrl+S on a selected local link (a link to a local file, from a
  local page). Expected: the notice `Ctrl+S: only web files can be downloaded`.
- [ ] 4.15 Ctrl+S during a page load. Expected: the notice
  `wait for the load, or press z`.
- [ ] 4.16 The blocked keys. Start a large download. Press Enter on a link,
  Backspace, Left, Right, `r`, `g`, `t`, `c`, `<`, `>`, `!` and Ctrl+S.
  Expected: each shows `download running: z stops it` and does nothing else.
  Scroll keys, Tab and `?` work.
- [ ] 4.17 `q` during a download. Expected: the quit prompt shows and the
  download goes on. Press `n`: it goes on. Press `q` then `y`: the program
  quits and `ls` shows no `.part` file.
- [ ] 4.18 A link to a ZIP file. Select it and press Enter. Expected: the
  ` Save to: ` prompt opens at once, no popup shows, and the page and the
  history do not change. A blank Enter cancels. Press Backspace afterwards
  and check that the history is as before. Do it again and accept the path.
  Expected: the file downloads.
- [ ] 4.19 `t` on a ZIP link. Expected: the save prompt opens, and no new tab
  opens.
- [ ] 4.20 A link with `Content-Disposition: attachment` (a server that sends
  it). Expected: the save prompt opens with the file name of the header.
- [ ] 4.21 A read-only filesystem (a read-only floppy or a disk set read-only,
  if you have one). Save a file to it. Record: the exact wording. Expected:
  `html: cannot write <path>: read-only filesystem`.

## 5. Regression

- [ ] 5.1 The 0.6.0a keys: Down, Up, PgDn, PgUp, Home, End, Tab, Shift+Tab,
  Enter, Backspace, Left, Right, `g`, `r`, `z`, `q`, `?`. Expected: they work
  as before.
- [ ] 5.2 A slow page: scroll and follow links while it loads. Expected: as
  in 0.6.0a.
- [ ] 5.3 Quit html and run `ls /home/.cache/html`. Expected: the folder is
  empty. Run `df` before and after a session. Expected: the same free space.
- [ ] 5.4 Ctrl+C during a load and in a prompt. Expected: `html: interrupted`
  or exit code 130, and the screen is restored.
- [ ] 5.5 After quit, the resolution and colors are the same as before
  `html` started (check after a tab-out too).
