# In-game check: release 0.3.0a

Goal: check the loading screen, remote fetching and the error paths in
game. Run the steps in order. Mark each item pass or fail, and paste back the
exact text of every failure.

`<BASE>` is the raw URL of the repository source. Use the version path
`releases/0.3.0a/`, not `releases/latest`.

Needs: an Internet Card, and a server that allows web requests. Steps 1 and 2
need no card.

Note: the `tools/netprobe.lua` default `--base`
(`https://raw.githubusercontent.com/RainVaporeon/oc-html/main`) is not
pushed yet. A page on it gives a 404 until the push. The 404 body still
serves N10 (the body of an error answer).

## 1. Install

```
wget -f <BASE>/releases/0.3.0a/html-install.lua /home/html-install.lua
/home/html-install.lua
```

- 1.1 New install (no `html` yet): it prints `html-install: oc-html 0.3.0a`,
  one line per file with its size, and `installed 9 files`. `html --help`
  shows the usage.
- 1.2 Upgrade over 0.2.0a (run the installer on a computer that has 0.2.0a):
  it prints the same lines (`html-install: oc-html 0.3.0a`, one
  `<path> <size> bytes` line per file, `installed 9 files`). The upgrade
  replaces the old files: no `.old` or `.new` file stays in
  `/home/bin` or `/home/lib/html`. The new file `/home/lib/html/url.lua`
  exists. `html --help` still works. `--stats` is gone from the help.
  A successful upgrade never prints `; old files kept`. That text ends the
  error line `html-install: <reason>; old files kept` only when an install
  fails after writing has started (the old files are put back). A failed
  check before any write prints `html-install: <reason>` with no suffix.

## 2. Local page

Make a page: `wget -f <BASE>/tests/pages/large.html /home/large.html` (about
1 MB). For a small page, use any `.html` file from `tests/cases/`.

- 2.1 `html /home/large.html`: the frame and the status line
  (`Loading /home/large.html...`) show at once, before any text. The status
  shows the phases and a KB count that rises to `... KB of ... KB`.
- 2.2 After the load, Up, Dn, PgUp, PgDn, Home and End scroll.
- 2.3 `q` shows ` Quit? (y/n)`. `y` quits with the screen restored, and
  `echo $?` gives `0`.
- 2.4 A page whose widest line is wide: no line is wider than the width
  minus 1 (no wrap glitch at the right edge).

## 3. Remote pages

- 3.1 `html http://example.com`: the status goes through
  `Connecting to example.com...` and `Waiting for response...`, then the
  page shows. `q`, `y` quits.
- 3.2 An https page: `html https://example.com`. The page shows.
- 3.3 A redirect: `html http://github.com` (http to https), or
  `html "https://httpbingo.org/redirect-to?url=http://example.com/"`. The
  status shows `Redirect to <url>...` and the page of the target shows.
- 3.4 A 404 page: `html https://httpbingo.org/status/404`, or
  `html https://example.com/missing`. The status line or the page shows
  `[HTTP 404]` and the error page body shows. Note whether the body is empty
  (this is N10).
- 3.5 A large page, about 1 MB: use a server you control, or
  `html <BASE>/tests/pages/large.html` after the push. The status line
  byte count rises while loading. The first screen shows before the end of
  the load.
- 3.6 Optional: a page whose body breaks off (an error page that stops
  before its end, or a server you can cut). The popup shows the error text
  and `[OK]`. Any key or a click on `[OK]` closes it. Mark it skipped if no
  page is found.

## 4. Ctrl+C

- 4.1 During connect: `html http://example.com:81/` (a host that does not
  answer). Press Ctrl+C. The program prints `html: interrupted`, the screen
  is restored, and `echo $?` gives `130`.
- 4.2 During a large load: start `html <BASE>/tests/pages/large.html` (or a
  large local file) and press Ctrl+C while the KB count rises. Same result:
  `html: interrupted`, screen restored, exit `130`.

## 5. q during a large load

- 5.1 Start a large load and press `q`. ` Quit? (y/n)` shows, and the KB
  count still rises (the load goes on).
- 5.2 Press `n`. The prompt goes away and the load continues to the end.
- 5.3 Start it again, press `q`, then `y`. The program stops, the screen is
  restored, and `echo $?` gives `0` with no message.

## 6. Bad arguments

- 6.1 `html http://`: one line `html: invalid URL: http://` prints, and
  `echo $?` gives `2`. The screen does not flash (no frame draws first).
- 6.2 `html ftp://example.com/`: `html: unsupported URL scheme: ftp`, exit
  `2`, no frame.
- 6.3 `html /home/missing.html`: `html: file not found: /home/missing.html`,
  exit `1`.
- 6.4 `html --print http://example.com`: the page prints as text and the
  program exits with `0`. No frame draws.
- 6.5 `html --width 1 /home/large.html`: a usage error
  (`html: --width needs a whole number from 2 to <maximum>`, then
  ` (see html --help)`), exit `2`. The maximum is the GPU maximum.

## 7. Rendering rules

Make `/home/r.html` with these lines (`edit /home/r.html`) and run
`html /home/r.html`:

```
<p>one <b>bold <i>both</b> italic</i> plain</p>
<p>a < b and 3 < 4
<pre>
first line
second</pre>
<br><p>after a leading br</p>
<select><option>x<option>y</select>
```

- 7.1 Misnested tags keep their styles (italic still shows after `</b>`).
- 7.2 A `<` with no `>` shows as text.
- 7.3 `pre` drops its first newline (no blank line before `first line`).
- 7.4 No blank line from the leading `<br>`.
- 7.5 Each `option` starts on its own line.

## 8. netprobe

Follow `docs/ingame/netprobe.md` in full:

1. Fetch and run the probe (sections 1 and 2). Expected: `netprobe: [1/9]`
   to `[9/9]`, exit `0`, and `/home/netprobe.txt` starts with
   `#netprobe v1`.
2. N8 (section 3): run again with `--out /home/netprobe-ctrlc.txt` and press
   Ctrl+C once while it waits for `http://example.com:81/`, and once while
   it reads the large page (run it twice, one Ctrl+C each). Expected: exit
   `130`, and the report holds `net.probe.interrupted=true` and
   `net.probe.interrupted_at=<section.step>`. Note how long the stop took.
3. N13 (section 4): run `--leak --out /home/leak1.txt`, then without a reboot
   `--out /home/leak2.txt`, and compare `net.limit.opened`. Reboot after.
4. Copy `/home/netprobe.txt` (and the other reports) to `./datacollection/`.

Remember the note at the top: with the default `--base`, the large page and
`AGENTS.md` give a 404 until the push. Pass `--base <BASE>` to a pushed
copy to avoid it.
