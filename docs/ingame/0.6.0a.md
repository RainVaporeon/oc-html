# In-game check: release 0.6.0a

Goal: check interactive loading in game. While a page loads, the user can
scroll, select and follow links in the part that is already laid out. Run the
steps in order. Mark each item pass or fail, and paste back the exact text of
every failure.

Note: the repository is not pushed yet. Copy the files by hand as for 0.5.0a
(the release folder `releases/0.6.0a/`, or `html-install.lua` from it, goes
into the game by the way you used for 0.5.0a). Then `<BASE>` below means that
copy.

Needs: an Internet Card, a server that allows web requests, a keyboard with
NumPad, and a stopwatch (or a clock) for the reaction times.

## 1. Install and upgrade

```
wget -f <BASE>/releases/0.6.0a/html-install.lua /home/html-install.lua
/home/html-install.lua
ls /home/lib/html
```

- 1.1 New install: it prints `html-install: oc-html 0.6.0a`, one
  `<path> <size> bytes` line per file, and `installed 11 files`.
- 1.2 Upgrade over 0.5.0a: the same lines. No `.old` or `.new` file stays in
  `/home/bin` or `/home/lib/html`. It never prints `; old files kept`.

## 2. A slow page

Use a slow page: a large Wikipedia article, or `<BASE>/tests/pages/large.html`
served by a server, or any host that is slow to answer. Start each test with
a page on screen (for example `html /home/c.html` from the 0.5.0a checklist,
with a link to the slow URL) and follow the link, or press `g` and enter the
slow URL. Use the stopwatch where a time is asked.

- 2.1 The status line shows `Loading <n> KB of <m> KB` while the page loads
  (with `<m>` when the server sends a length). Expected: the number grows.
- 2.2 The first lines appear while the page still loads. How long until the
  first screen is usable (3 KB/s or so)? A: Realistically 9-10Kbps measured; for `wikipedia.com` it takes until ~90/120Kb, about 10 seconds.
- 2.3 Scroll with Down, PgDn and Up while the page loads. Expected: the
  page scrolls and the view never moves by itself when new lines arrive.
- 2.4 End and PgDn while the page loads. Expected: paging stops at the last
  complete screen. It does not show half-finished lines.
- 2.5 Tab and Shift+Tab while the page loads. Expected: a link joins the
  selection when its first line is complete. The selected link shows in
  reverse video and its URL shows on the status line.
- 2.6 Up and Down while the page loads. Expected: they move between the
  links that are loaded. When no link is on screen, they scroll one page.
- 2.7 Keys respond while the program renders. Press Down five times quickly.
  Reaction time of the first key: A: Near immediate (expected under about 0.2 s)
- 2.8 No key is lost. Press Down, Down, Tab, Down quickly during a load.
  Expected: each key does its action.
- 2.9 The old page stays scrollable while the new one connects. Follow a link
  to `http://example.com:81/` (no answer), and press Down or PgDn while the
  status shows `Connecting`. Expected: the old page scrolls.

## 3. Leave a page that is loading

For each step, wait until some lines of the slow page show, then press the
key.

- 3.1 Select a loaded link and press Enter. Expected: the load stops and the
  program opens that link.
- 3.2 Press Backspace (also try Left and `z` on later runs). Expected: the
  load stops and the program goes back at once, as in 0.5.0a. Reaction time:
  Yes
- 3.3 Press `r`. Expected: the load stops and the page loads again from the
  start.
- 3.4 Press `g`, then Esc. Expected: the prompt closes and the load goes on.
  Press `g`, type a URL and press Enter. Expected: the load stops and the
  program goes to the URL. A: Correct, but `Esc` exits the screen, instead a blank input is used to substitute exit, which works.
- 3.5 Press Right at the last history entry (for example on the first page
  of the session, or after Back and then a new link, which cuts the forward
  entries). Expected: nothing happens and the load goes on.
- 3.6 Press Right on a page that has a later history entry, during a load.
  Expected: the load stops and the program shows the later entry.
- 3.7 `q` during the load, then `n`: the load goes on. Again, then `y`: the
  program quits.

## 4. The cache and a page that was left

- 4.1 Open page A, follow a link to a slow page B, and press Enter on a
  loaded link of B before B finished. Then press Backspace to B. Expected:
  B downloads again (the loading status shows). A page left before it
  finished is not cached.
- 4.2 Open B and let it finish. Follow a link, then press Backspace.
  Expected: B shows at once, with no download (the cache serves it).
- 4.3 Quit html and run `ls /home/.cache/html`. Expected: the folder is
  empty. Run `df` before and after a session. Expected: the same free space.

## 5. Errors and limits

- 5.1 A page too large for the memory (for example the 1 MB page) while you
  scroll it. Expected: the popup shows the memory message and `[OK]`, the
  program keeps the session, and Reload works.
- 5.2 Ctrl+C during phase 1 (`Connecting`) and during the body. Expected:
  the program exits with `html: interrupted` and the screen is restored.
- 5.3 `z` during phase 1 and during the body. Expected: the previous page
  shows again.

## 6. Depth

- 6.1 Repeat 2.3 to 2.5 on a depth-4 and on a depth-1 screen. Expected: the
  selected link is visible and the status line is readable.

## 7. What to paste back

- The pass or fail of each numbered item.
- The times of 2.2, 2.7 and 3.2.
- What 3.5 and 3.6 did.
- The result of 4.1 to 4.3.
- The exact text of every popup or error.
